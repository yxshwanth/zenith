# BUG-003: hunt seed 192 KV diverges from identical logs

Status: fixed
First failing commit: post StrongGet fence-Reply (BUG-002 partial)
Fix commit: afterSync append in persistThen (raft.go), session restore in drainPendingSnap/Crash (replica.go)
Invariant violated: R4 (applied state vs committed prefix); Porcupine
Seed and simulator version: 192, huntFaults, ExploreHunt(40)
Exact replay command: `ZENITH_HUNT_SEED=192 go test ./internal/replica -run TestHuntOneSeed -count=1`
Fault assumptions: same as BUG-002

## Minimal sequence
All 3 nodes have identical committed logs through index 33. Last k1 Put is index 25 (k1=v1). n1 has k1=v1 (correct), n2 and n3 have k1=v2 (stale). Get k1 at client time 71 returns v2 after Put k1=v1 acked at 56.

## Incorrect result
Porcupine Fail. Replicas with the same committed prefix must hold the same KV.

## Expected result
Pass. All nodes converge to the same KV after applying the same log.

## Root cause
`persistThen` set `afterSync = then` (replace, not append). When a follower received AppendEntries, Raft advanced `lastApplied` and queued Apply effects in `afterSync`. If a second AppendEntries arrived before the sync completed (common under SyncFailPermille=100), `persistThen` replaced `afterSync`, losing the first batch of Apply effects. The KV on that follower missed those writes.

Additionally, `drainPendingSnap` and `Crash` did not restore sessions from snapshot state. This would cause incorrect session dedup after InstallSnapshot, though in seed 192 the primary path was the `afterSync` replacement.

## Why previous tests missed it
Sync failure rate was 0 in non-hunt tests. `TestStrongGetFence` and `TestCrashDuringInstallSnapshotKeepsPrefix` use reliable disks.

## Fix and reasoning
- `persistThen`: `afterSync = append(afterSync, then...)` so Apply effects accumulate across sync retries.
- `drainPendingSnap`: restore `r.Sessions` from `st.Sessions`.
- `Crash`: restore `r.Sessions` from `st.Sessions` when loading snapshot.

## Regression coverage
`testdata/regressions/hunt-192.json` expect ok. `ZENITH_SWEEP=500` clean.

## Remaining limitation
None. The `afterSync` append fix covers all effect types, not just Apply.
