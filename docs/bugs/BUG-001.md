# BUG-001: hunt seed 66 Fail from dropping in-flight Puts

Status: fixed
First failing commit: hunt explorer (ExploreHunt + CheckKVHistory strip)
Fix commit: CheckHistory flush + Porcupine unbounded unknown Puts
Invariant violated: none in Raft; checker completeness (docs/invariants.md three-way history)
Seed and simulator version: 66, huntFaults, ExploreHunt(40), module github.com/yxshwanth/zenith
Exact replay command: `ZENITH_HUNT_SEED=66 go test ./internal/replica -run TestHuntOneSeed -count=1`
Fault assumptions: MaxNetDelay 8, DropPermille 120, DupPermille 80, MaxDiskDelay 4, SyncFailPermille 100, ElectJitter 16

## Minimal sequence
Propose Put k0=v1 (request h19, invokedAt 33). Client never gets a Reply. Later StrongGet k0 completes with v1 (invokedAt 40). Prefix matching holds. Nodes agree on a later k0 value after more puts.

## Incorrect result
Porcupine Fail: completed history has Get k0=v1 and no completed Put of k0=v1.

## Expected result
Inconclusive. The Put is still pending; the Get is explained by that in-flight write.

## Root cause
`CheckKVHistory` stripped Unknown ops before Porcupine. `CheckHistory` never flushed `pending`. An applied but unacked Put disappeared from the model.

## Why previous tests missed it
Put-only explore never recorded Gets. Unit fixtures either completed every Put or used Unknown without a Get of that Put's value.

## Fix and reasoning
Flush leftover `pending` as Unknown. Keep unknown Puts in Porcupine with unbounded return and successful put output. Unknown Gets stay out of the model. Illegal completed subsets still Fail.

## Regression coverage
`TestCheckKVHistoryPassFailInconclusive` inflight-put case. `testdata/regressions/hunt-66.json`. `TestHuntOneSeed` with `ZENITH_HUNT_SEED=66`.

## Remaining limitation
Unknown Gets are not modeled (no sequential output). Digest-reject `onReply` still drops pending without a history row. After this fix the hunt finds BUG-002 (seed 141), a real stale StrongGet.
