# BUG-002: hunt seed 141 stale StrongGet after acked overwrite

Status: fixed
First failing commit: ExploreHunt + huntFaults
Fix commit: afterSync append (raft.go), ackedIndex high-water mark (replica.go), fence Reply required (replica.go)
Invariant violated: client KV linearizability (Porcupine)
Seed and simulator version: 141, huntFaults, ExploreHunt(40)
Exact replay command: `ZENITH_HUNT_SEED=141 go test ./internal/replica -run TestHuntOneSeed -count=1`
Fault assumptions: MaxNetDelay 8, DropPermille 120, DupPermille 80, MaxDiskDelay 4, SyncFailPermille 100, ElectJitter 16

## Minimal sequence
Put k0=v5 at index 24 acked. Put k0=v3 at index 27 acked (client time 59-60). StrongGet k0 invoked at client time 65 returned v5.

## Incorrect result
Porcupine Fail. A Get that starts after Put k0=v3 completes must not return v5.

## Expected result
Pass. After fix, the fence commits at an index that includes the acked Put, and `afterSync` append ensures all Apply effects reach the KV layer.

## Root cause
Three layered issues:
1. `persistThen` replaced `afterSync` instead of appending. When a second `onAppendEntries` arrived before sync completed, the first batch of Apply effects was lost. KV missed writes, so the leader's KV was stale when the fence Reply sampled it.
2. `StrongGet` did not verify the fence committed at an index at or past the last acked write.
3. `StrongGet` used `Role()==Leader` instead of waiting for an actual fence Reply.

## Why previous tests missed it
Put-only explore never Gets. `TestStrongGetFence` uses a healthy cluster (no sync failures). Seed 66 (BUG-001) was a checker false positive that hid this class.

## Fix and reasoning
- `persistThen`: `afterSync = append(afterSync, then...)` so deferred Apply effects accumulate across retries.
- `onReply` for successful Puts: parse `ok:<index>` from Reply payload, track `ackedIndex` high-water mark.
- `onReply` for fences: parse `ok:<index>`. If fence index < `ackedIndex`, reject (StrongGet records Unknown).
- `StrongGet`: requires successful fence Reply and samples KV at Reply time.

## Regression coverage
`testdata/regressions/hunt-141.json` expect ok. `TestStrongGetStaleLeaderUnknown`. `ZENITH_SWEEP=500` clean.

## Remaining limitation
None for the sim harness. Production `ReadIndex` path in `check.go` should be reviewed separately.
